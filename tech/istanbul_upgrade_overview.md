伊斯坦布尔升级简介
===

Hacash 从2018年白皮书发布、2019年挖出第一个区块，已经稳定运行了6年，其PoW经济模型的丰富性和加密健全货币理论的前瞻性得到了长期而稳固的证明。

本次升级（借用城市名称命名为伊斯坦布尔）综合了多年来累计提出和开发的各项重大技术，包含资产发行、合约建构和可编程性等诸多方面，包括 HIP-20、TDEX、AST（HIP-16） 和 HVM 及 P2SH（由 Hacash.com 研发）。自此，Hacash 在公链技术上实现了革命性突破：由一条纯粹的货币发行和支付公链变身为支撑世界货币、资产和金融体系持续创新及安全运转的生态系统基础。

此文档将简要介绍这一系列重大技术，勾勒出一个以健全货币为核心的加密金融新世界。


### HIP-20

此协议被成为 HIP-20 (Hacash Improvement Proposal) 而不是 HRC-20 (Hacash Request for Comment) 的原因是，在 Hacash 上发布的资产并不是一个寄生在 HVM 层的二等公民，而是有着和 HAC、HACD 和 BTC 完全相同待遇的一等资产。

这意味着Hacash所有技术层基础设施，包括可读合约、条件合约、通道链二层支付等，都将完全对 HIP-20 资产开放，而并不需要在 VM 层面来再次编程模拟。例如，一个 HIP-20 资产和 HAC 的原子互换交易，就像现在链上的 HACD 和 HAC 的原子互换一样，可以被天然支持。再比如，在通道链网络中，通过支付服务商提供的货币兑换，可以立即实现顾客支付 HAC，而商家实时收到的是 USDT。

这种区别于智能合约编程的的链原生资产发行新范式，可以带来安全性和用户友好性的双重提升，公链将从单一的技术性智能合约编程平台，扩展成一个原生资产的生态空间。

当然，通过在 HVM 内的编程，也完全可以实现传统合约资产的发行及交易。


### TDEX

这是另一项以 Hacash 可读合约为基础的链上自动化交易协议，全称为 Transaction Decentralized Exchange 。

有别于已经实现的链上原子互换（需要明确指定交易双方地址并都签署整个交易），此项技术不依赖对手方实时在线签名，也无需具体指明跟谁交易。交易方仅需要签署交易的“一半”即可：在什么条件下、收到多少HAC、支付多少USDT。然后，将其广播给第三方清算商，由它们来匹配多个交易需求，组合成一笔交易上链，其中撮合的差额则成为了清算商的利润。当然，清算商也可以成为客户的交易对手来提供流动性，从而兼具做市商身份。

这是一种链上订单簿清算系统，依赖 Hacash 原创的单笔交易清算技术：即在单笔交易内维护一个多种代币的清算池，不同的订单以这笔交易的代币池为交易对手，收取和支出不同的代币，系统会在交易上链时检查这些代币的转移情况，在确保所有代币都转移到了各自的账户中，代币池的所有代币差额都清零的情况下，即成功完成清算并确认整个交易，否则拒绝上链。

这种交易方式不依赖于任何唯一的交易ID来去重，这意味着同一笔订单可以多次上链，直到耗尽用户单边代币余额。例如签署一个以 1000 USDT 买入 100个 HACD 的订单，且账户内包含 5000 枚 USDT，那么这笔订单将可以上链 5 次，耗尽5000个USDT，并一共收到 500 个 HACD。

当然，可以通过在订单内指定过期区块高度、代币余额检查等条件，来实现交易有效期限或指定交易次数、金额等高级功能，或者实现订单的单次执行。

相比于 AMM 方式固有的滑点、MEV和流动性代币锁定等缺陷，这将带来巨大的用户友好性、交易灵活性和资金利用效率，并基本完全避免了合约编程的安全漏洞，也将结束大多数如今仍频繁发生并给行业造成巨大损失的黑客盗币事件。

可以预见，TDEX 的创造将为下一代链上资产清算系统的大规模普及奠定基础。


### AST

这项技术来源于 [HIP-16](https://github.com/hacash/doc-chinese/blob/main/HIP/protocol/account_and_syntax_tree_abstraction.md) 提案中的可读合约抽象语法树部分。可以把这项技术称为“条件合约（Conditional Contract）”或“可读合约抽象语法树（Readable Contract Abstract Syntax Tree）”

具体来说，通过增加 If 和 Select 等按条件执行交易的结构性 Action ，就可以在可读合约架构下，达成传统编程语言中的条件分支、模式匹配等逻辑语义，实现基础且清晰的可编程性。

相比于在 HVM 层进行图灵完备的编程，AST 方式的灵活性是受限的。但这将带来巨大的好处：

1. 安全、可审计性。因为没有用字节码虚拟机实现编程，而是采用类似抽象语法树的数据结构来定义程序逻辑，并且严格限制了逻辑边界（比如禁止循环），这给人工直观性审计或形式化验证合约的安全性提供了极大便利，几乎可以做到完全避免传统 VM 编程带来的合约漏洞。

2. 用户友好性。无需依靠专业程序员的编程，没有技术背景的用户现在也能通过点击、拖动和填写表单的方式创建自己想要的金融合约，并且没有潜在漏洞。

3. AI 适配。由于条件合约的可编程逻辑通过非常明确的数据结构来实现，那么给 AI 发送自然语言指令（例如：在今年圣诞节之前，要求Bob给我转账 20 个 HACD ，如果成功，我将支付给他300个 USDT，如果不成功，则什么也不做），生成完全正确无歧义的金融合约，将可能成为未来普通人使用链上金融的主要方式。

4. 跨链互换原语。由于可以在同一笔交易里定义分别在 A 链和 B 链执行的逻辑，并精确控制时间锁、代币金额等条件，Layer 3 层的资产跨链将以此为技术基础。

AST 条件合约的可编程性居于一维组合的事务性可读合约和 HVM 智能合约之间，但极大地提升了链上金融操作的安全性，这为传统大资金能够积极参与 DeFi 扫清了一个严重阻碍。


### HVM

Hacash虚拟机（HVM）专为安全金融应用而设计，具有强大的账户抽象和状态优化功能。非常适合DeFi、BTCFi、PayFi和稳定币。

其在智能合约的安全性和架构的清晰度方面均优于传统区块链 VM，目前已经编写了多个经典测试用例：

1. [比特币 SAT 和 HAC 互换的 AMM](https://github.com/hacash/fullnode/blob/main/vm/tests/amm.rs)  

2. [HACD 的碎片化代币协议](https://github.com/hacash/fullnode/blob/main/vm/tests/hacds.rs)

3. [HRC20 智能合约代币](https://github.com/hacash/fullnode/blob/main/vm/tests/hrc20.rs)

4. [链上合约继承实现](https://github.com/hacash/fullnode/blob/main/vm/tests/inherit.rs)

HVM 源码现以合并到 [Fullnode](https://github.com/hacash/fullnode) ，请查看 [https://hacash.com/HVM](https://hacash.com/HVM) 以了解更多。


### P2SH

P2SH 借鉴了比特币的 Pay-to-Script-Hash 技术，也支持 MAST (Merklized Abstract Syntax Trees) ，并且，进行了如下重大技术升级：

- 可以将 HAC、BTC、HACD 和 任何 HIP-20 资产都发送到这个脚本地址进行统一管理

- 控制脚本支持完整的 HVM 可编程性

- 默克尔树验证哈希算法采用 SHA3，更加安全和高效

可以预见，结合 AST 条件合约，这项技术将成为 Hacash L3 多链生态跨链技术体系的核心环节。

最后，我们认为，这不仅仅是 Hacash 的升级，还代表了整个加密行业公链技术发展的最前沿。Hacash 将迎来全新的阶段，一个生态繁荣的时代即将开始。
